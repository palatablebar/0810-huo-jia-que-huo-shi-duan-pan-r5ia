# 批次操作

1. 用带异常样例做阶段预览，查看列数、必填值和冲突记录。
2. 执行批次后，在业务阶段定位异常分组并核对原始记录键。
3. 修复来源文件，重新上传并执行。历史批次保留供复核。
4. 对账无差异且无坏行时可签发。对仍有差异的版本可填写暂缓意见。
5. 导出复核证据并保存于交接记录。

## 单组更正与有效批次

门店只补交一个业务组的更正时，不必让未变化的组重审：

1. 先确认首发批次已签发（历史列表带"有效"标记）。
2. 在"更正基线"选择该有效批次，上传只含更正业务组的 CSV 后执行。
3. 更正组若能独立完成营业窗、缺货率和阈值判定，标记为"重新审核"；其余组标记"沿用原结论"并保留来源批次与指纹。
4. 更正组信息不足（缺营业窗或阈值）或重审未通过时，整组保持原有效结果，阻断原因列在 `blocks`，批次不可签发；不会把片段拼进旧版形成混合版本。
5. 对账通过后签发：新批次成为唯一有效批次，旧版自动失效但证据完整保留。签发失败（含阻断）时事务回滚，旧版仍为有效批次。
6. 同一更正对同一基线重复上传返回同一批次，不会重复生成；继续更正时以当前有效批次为基线形成血缘链。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次。恢复时使用原 Docker Compose 数据卷；旧版数据库首次访问时自动补列，已签发批次迁移为有效基线。
